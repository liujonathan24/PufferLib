# Cluster AV — function-local statics audit

Generated by `tools/find_globals.py --func-statics` after Cluster AU
(8 commits, ~74 file-scope mutables migrated).

**83 `static T x;` declarations inside function bodies** across the
NetHack source tree (excluding lex/yacc auto-gen). Each is persistent
across calls — same hazard as a file-scope global under multi-env
vecenv, since `static` inside a function = lifetime of the process.

## Filtering

Most of the 83 are `static char buf[N];` "return-by-static-buffer"
idiom — those return-string functions write the buf on every call, so
even if a coroutine yield interleaves two envs the corruption is
contained to the return value (caller has already consumed it before
the yield). Roughly 50 fall in that category.

What's left (~30 truly persistent function-statics) is the actual bug
surface for Cluster AV:

## Hypothesis for the N=256 shopkeeper-eshk-NULL crash

The diagnostic agent (Cluster AV-a) is investigating in parallel.
Candidates from this audit that touch shop / monster code:

1. **`hack.c:2168-2171 spoteffects`** — the `spottrap` field is a
   `struct trap *`. If a shop floor trap pointer is cached, then env A's
   trap is freed (or the level is reset) and env B's spoteffects walks
   into that pointer thinking it's a shop trap → wrong room number →
   wrong monster lookup → not-a-shopkeeper.
2. **`shk.c:718 pickmovetime`** — pet pickup time in shop.
3. **`mon.c:2658 elemental_clog msgmv`** — elemental-monster clog,
   could touch shopkeeper monsters.
4. **`rnd.c:88 rn2_on_display_rng seed`** — wrong RNG → wrong monster
   chosen → confused shopkeeper lookup.

## Migration pattern (same as Cluster AU)

For each function-local static `static T x;`:

1. Add `T s_<func>_<name>;` to `nle_ctx_t` in `nle.h` under a
   `/* Cluster AV — function-local statics */` block at struct end.
2. Replace the static decl with a `#define <name> (current_nle_ctx->s_<func>_<name>)`
   at the **top of the file** (so it's visible to the function).
3. **Careful**: the variable lifetime now changes from "process" to
   "per-env-lifetime" (calloc-initialized at every `nle_start`). If the
   original code relies on "initialized once at process start", you may
   need to set it explicitly in `nle_start()` — but in practice these
   variables are written before they're read on each game tick, so
   calloc-zero is usually safe.

## Fanout proposal

Group into ~8 batches by file locality. The CRITICAL group (rnd.c,
trap.c, hack.c spoteffects, mkmaze.c movebubbles) goes first; the
medium and low groups can fan out in parallel after Group A lands.
