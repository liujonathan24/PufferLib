# exp_018 — NetHack determinism verification harness

Standalone harness at `ocean/nethack/verify_determinism.c`. Records a per-step
SHA1 fingerprint of (observations || reward || terminal) into a binary golden
file, and replays it against a fresh env to verify bit-identical trajectories.
Built to support the upcoming "functional NetHack" refactor (globals in a
struct): the new version must replay any golden file produced by the current
version with zero mismatches.

## Build

From the PufferLib repo root:

```bash
clang -O2 -Wall -Wextra -std=gnu11 \
    -I./vendor/nle/include -I./ocean/nethack \
    -DNETHACK_USE_BLSTATS=1 \
    ocean/nethack/verify_determinism.c \
    -o verify_determinism -ldl -lpthread -lm
```

Notes:
- Must be run from repo root (the env's `nethack_load_lib` resolves
  `./vendor/nle/lib/libnethack.so` relative to cwd, and the vardir setup
  expects `./vendor/nle/nethackdir/nhdat`).
- Override either with `NETHACK_LIBPATH=...` and/or `NETHACKDIR=...`.
- `NETHACK_USE_BLSTATS=1` enables score/HP/depth/etc. in the obs buffer so
  any divergence is easy to debug. The replay binary must be compiled with
  the SAME `NETHACK_USE_*` flags as the recording binary — the header carries
  `obs_size` and replay refuses to run on mismatch.
- The harness does NOT link PufferLib. It directly `#include`s `nethack.h`
  and provides its own `c_reset_seeded` variant that passes a fixed
  `nle_seeds_init_t{seeds={S,S}, reseed=0}` to `fn_start`. `nethack.h` is
  untouched.

## Invocation

```bash
# Record a golden file
./verify_determinism record --seed 42 --steps 1000 --action-seed 99 --out /tmp/g1.bin

# Replay it
./verify_determinism replay --in /tmp/g1.bin

# Replay + dump SHA1 of libnethack.so's writable segments at the end
./verify_determinism replay --in /tmp/g1.bin --bytewise
```

Exit codes: `0` ok, `1` usage / I/O error, `2` env init failure, `3`
trajectory mismatch (the first mismatch is reported with action, expected vs
actual hash/reward/terminal, the 21x79 chars grid and the first 32 obs bytes).

Action stream: generated by SplitMix64 seeded with `--action-seed + 0x12345`.
The same `--action-seed` produces an identical action stream regardless of
libc/platform; we deliberately avoid `rand()/srand()`.

NLE seeding: both `seeds[0]` (core) and `seeds[1]` (display) are set to
`--seed`. `reseed=0` disables NetHack's anti-TAS reseed mechanism — without
this, NLE re-seeds from `time()` inside `fn_start` and you cannot get
determinism.

## Binary format

Little-endian, packed:

```
GoldenHeader (40 bytes):
  uint32 magic        = 0x4E484447 ('NHDG')
  uint32 version      = 1
  uint64 seed
  uint64 action_seed
  uint64 n_steps
  uint64 obs_size     = NETHACK_OBS_SIZE
  uint32 num_actions  = NETHACK_NUM_ACTIONS
  uint32 use_blstats  = NETHACK_USE_BLSTATS

GoldenRecord (32 bytes), repeated n_steps times:
  int32  action       (index into NETHACK_ACTION_TABLE)
  uint8  hash[20]     (SHA1 of obs || reward || terminal)
  float  reward
  uint8  terminal
  uint8  _pad[3]
```

For 1000 steps, file size = 40 + 1000 * 32 = 32040 bytes.

## Sanity test results (1000 steps, seed=42, action-seed=99)

1. **Compile with `-Wall -Wextra`**: clean. (`nethack.h` and `profile.h`
   carry a handful of `-Wunused-*` warnings unrelated to this harness; we
   `#pragma clang diagnostic` them out across just the include and
   re-enable warnings for our own code.)
2. **record**: `record: wrote 1000 steps to /tmp/g1.bin (obs_size=1767)`.
3. **replay**: `replay: OK — 1000 steps match`.
4. **Determinism (`cmp /tmp/g1.bin /tmp/g2.bin` after a second record with
   the same seeds)**: **IDENTICAL**. Current env is deterministic given a
   seeded `nle_seeds_init_t` with `reseed=0`.

Additional checks:
- Negative control: `--seed 43` produces a file that differs from
  `--seed 42` starting at byte 9 (the seed field in the header). Replaying
  the wrong golden against the seed-42 trajectory triggers a mismatch on
  step 0 as expected.
- `--bytewise`: prints SHA1 of all writable LOAD segments of libnethack.so
  after replay; useful for byte-level state equivalence checks across env
  versions (e.g. once the functional refactor lands, the bytewise hash of
  the BSS-resident globals should still match after N steps).

## Non-determinism findings

None at the harness level. With `seeds_init_t{seeds={S,S}, reseed=0}`,
NetHack 0.9.1 (as vendored under `vendor/nle/`) is bit-deterministic across
runs in the same process layout — at least over 1000 steps with random
actions. The harness is therefore a usable oracle for the upcoming
functional refactor: any divergence after the refactor is a real bug, not a
seeding artifact.

(A longer, 100K-step golden is a separate task; not produced here.)
